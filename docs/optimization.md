## 当前重构（2026-11-20，schema 15）

- 定时鉴权从 23 个查询列减为 15 个，复用扫描结构，保留周期切换时事务内重新读取、持久预留与撤销保证。
- 概览只读取最多 12 条任务摘要；历史按 ID 游标分页，失败总数不依赖当前页。浏览器切页取消读取，提交后的后台任务继续执行。
- JS/CSS 按需生成一次 gzip，缓存只接受真实嵌入资源；Vary 与表示独立的 ETag 保证升级及 304 正确性。页面仍采用原生 ES 模块和按需加载。
- 恢复只在内存保存小型清单和路径，数据库与证书暂存到私有目录。完整 age 认证、大小限制与 SQLite schema 检查通过后才发布；失败清理临时材料。scrypt 自身的固定内存成本仍然存在。
- 删除节点及 VPN profile 的占位 UUID/密码与旧共享凭据命令的测试实现。账户列表合并名称/技术 ID、显示真实额度进度，节点编辑按基本/传输/安全分组。

Windows amd64 / i5-9400F / Go 1.27.3，100 个活跃授权、500ms × 3：每次分配从约 163,096 B / 1,995 次降到 87,024 B / 980 次，分别减少约 46.6% / 50.9%。最终耗时为 0.529–0.549 ms；前后耗时受并行构建和本机调度影响，不作为严格加速比。64 KiB 持久计量仍为 1.15–1.20 ms/次，SQLite 持久性未降低。原始样本和系统验收范围见[本轮记录](validation/2026-11-20-project-refactor.json)。

## 历史重构（2026-11-19，schema 14）


- `serverconfig` 持有独立强类型节点契约，常规端口查询直接读取节点，不构造动态核心对象；JSON 仅在核心发布和外部边界生成。
- 编译缓存覆盖不可变的解析验证，显式包含解析器版本；授权、额度、撤销及核心文件依赖仍实时核查。
- 授权快照复用扫描参数切片，减少每个凭据的临时分配，计量持久性及 64 KiB 预留不变。
- 控制队列最多合并 16 个连续账户命令后统一发布；各任务有独立结果，配置/服务任务作为顺序边界。
- 模板子编辑器只渲染当前类别，资源短列表隐藏多余工具栏，页面请求和弹窗归属共用取消机制。
- 移出八个测试专用辅助函数，简化过时实施汇总；测试夹具保留在 `_test.go`，生成类型不嵌入发行二进制。

本轮数值与验证范围见 `validation/2026-11-19-modular-refactor.json`，不能从微基准推导生产网络吞吐提升比例。

## 较早阶段的优化与测量

### 账户编译结果复用

账户服务只缓存不可变编译结果：最多 128 条，正文和诊断的估算容量预算 16 MiB，有效期 5 分钟。相同输入的并发请求合并编译；每次请求仍读取账户状态并校验授权及输出，公开用量仅生成授权选中的格式。缓存不持有数据库连接或授权决定，返回给调用方的正文和诊断与缓存分离。

本轮重构前的测量：Windows amd64 / i5-9400F / Go 1.27.3，256 个 Trojan 节点的 URI 输出，三次 300ms 基准：未缓存的耗时中位数 3.205 ms，缓存命中后 1.989 ms；累计分配中位数分别为 1,287,908 B 和 867,438 B。此基准包含编译计划、渲染及每次格式校验，不包含数据库读取、节点摘要计算、网络传输或生产常驻内存；不能推导代理吞吐提升。原始数值和命令见[质量收尾验证](validation/2026-11-19-subscription-quality.json)。

### 订阅 schema 5 与账户导出

- 重名分配维护每个原名的下一后缀，节点和策略组共用稳定分配器，避免 4096 个重名造成平方级扫描。
- 解析字段描述按固定 schema 复用；一次输出计划只获取一次客户端协议矩阵，账户导出不重复执行能力筛选。
- sing-box/Mihomo/URI 字段映射分开，编码器显式注册；删除重复白名单检查及 subscriptions/local.json。测试夹具直接重建内联材料。
- 刷新抓取、渲染及核心验证在发布锁外完成，提交前复核配置/账户节点/核心；不覆盖并发记录。无效资源更新使用旧资源重新发布健康输出。
- Mihomo 校验按二进制身份、模式、校验目录与正文摘要缓存；单输出检测只展开目标来源并复用格式验证。
- TCP 连接限额位于 TLS 之下，标准服务器保留 TLS 状态和 HTTP/2；独立下载服务保留单独请求上限。
- 页面按实际账户返回客户端节点数、模板和验证，来源/集合/输出/分发局部更新；状态页移除空卡片和重复刷新区。

上述是当前实现。下列早期 schema 的测量保留为历史对照，不代表本次修改后的测量值。新的重名、渲染及计量基准在停止虚拟机与测试面板后记录，见本次验收记录。

当前短同名 VLESS 样例（4096 节点）累计分配 10,403,376 B，审查基线为 211,084,736 B。80 个汉字的重名基准约 11.26 MB/次；计量 Take/Complete 仍为 0 B、0 次分配。渲染新增字段检查后仍有固定开销，本机耗时样本波动，不宣称所有路径同比加速。命令与完整原始数值见[本次验证](validation/2026-11-19-subscription-unification.json)。

### 订阅专用投影与编译缓存（2026-11-19，订阅 schema 5）

调度改读独立 schedule.json，不再扫描大节点缓存；输出状态独立记录节点数量、验证和截断诊断。编译按选定节点及有效模板摘要复用产物，保持能力、引用、安全与核心身份检查，ParserVersion 控制来源解析缓存失效，CompilerVersion 控制渲染产物失效。面板下载 handler 复用同一个订阅视图缓存，授权始终每请求执行。

Windows amd64 / i5-9400F / Go 1.27.3，4096 个远端缓存节点及 4096 个本地节点，包含一个真实远端来源元信息；BenchmarkSubscriptionScheduleRead 使用 500ms、三次，专用调度读取中位数 0.112 ms / 3,987 B，完整投影读取 20.020 ms / 16,801,510 B。分配主要来自小型元信息，未缓存整个配置或放宽数据预算。该对照只衡量文件读取与解码，不证明代理吞吐或 VPS RSS 改善；旧扫描版测量保留在后面的历史记录。原始样本见 [订阅重构验证](validation/2026-11-19-subscription-refactor.json)。

### 公网访问、任务与模块整理（2026-11-19，schema 13）

- 服务身份统一到 `internal/servicecatalog`，VPNGate 接入核心与出口网关使用不同名称和工作区；固定服务列表不再创建搜索/分页控件。
- 面板和独立订阅共享传输验证及 TLS 缓存。证书对每 30 秒刷新，失效拒绝握手；可信代理 CIDR 在创建 handler 时解析一次。高级输出可共用面板 HTTPS，取消对独立监听的无效依赖。
- 主机编排拆分为服务查询、部署、单元安装、网关、网络及日志模块。移除账户配置的旧 JSON 回退、旧面板证书实现及无调用的日志/代理包装；证书解析与有效期共用 TLS 模块。
- 任务终态提交与保留清理分离，维护失败不终止 worker；保留策略支持数量/天数/详情预算，进行中的任务始终优先可见。管理员可标记处理、删除和批量清理。
- 项目 journald 使用独立命名空间与容量/时间目标，读取及下载有界；清理只轮转和回收项目历史日志。写入前检查配置与单元所有权，拒绝符号链接。
- 访问表单复用 TLS/代理字段，预览、保存、重启分步展示；独立助手验证新监听，失败恢复旧设置。恢复上传单独设定 2 分钟读取、3 分钟响应/前端等待预算。前端沿用原生模块、延迟工作区、可取消读取和单 SSE。

Ubuntu amd64 专用 VM（QEMU TCG、2 vCPU/2 GiB）中，4 个客户端持续 60.08 秒读取概览、权益与授权列表，共完成 2,145 次请求、0 错误；P50 为 40.80 ms，P95 为 96.19 ms。面板峰值 RSS 23.48 MiB，普通核心 29.79 MiB，未丢失进程。客户端每轮有 50 ms 等待，测量值是本机诊断基线，不代表最大容量、代理带宽或与 3x-ui/s-ui 的性能对照。原始指标和完整验证边界见[本轮记录](validation/2026-11-19-public-access-maintenance.json)。

### CI 启动与按需读取（2026-11-19）

- 初始化复用已校验产物，避免再次构建相同配置；失败重试从已提交配置重新构建。
- 配置页面仅查询 desired 与 revision，候选保存的两次版本核对仅查询 revision，避免复制无关的大配置字段；保持单次 SQL 快照一致性。
- HTML/JS/CSS 直接读取 embed 数据；现有 JS/CSS 的 ETag 只在首次访问计算，不缓存不存在的路径。
- 本机健康检查不占业务请求并发额度；隐藏或退出页面时取消 SSE 重连的在途会话读取。
- CI 使用独立启动器执行真实 `init`/`serve` 和 `/healthz`，成功停止进程并清理目录，失败保留数据和有界日志。

`BenchmarkConfigurationRead` 在同一个 SQLite 数据库中比较完整状态、desired 和版本查询，desired 与 applied 各约 1 MiB。三次样本中位数的分配字节分别为 4,253,224 B、2,114,895 B 和 1,092 B；只读 desired 的单次分配约减少 50%。该结果仅衡量数据库读取，未作为代理吞吐或整机 RSS 提升结论。复现：`go test ./internal/controlstore -run '^$' -bench '^BenchmarkConfigurationRead$' -benchmem -count=3`。本轮并行运行其他本地验证，耗时样本仅供诊断，详细数据见 [启动与读取验证记录](validation/2026-11-19-ci-startup.json)。

### 前后端一致性重构（2026-11-19）

- 权益页、分享创建和公开用量共用 `account_sharing` 的入口可用性判断；绑定摘要只查询实例/入站/协议，不读取密码或 UUID。未绑定时提供绑定操作，解绑后的旧链接显示原因。
- 出站编辑只写实际编辑的字段，支持 gRPC，并保留未知传输和对象形式 DNS 配置；复制也沿用同一保留规则。菜单在点击结束后收起，避免布局变化使相邻按钮丢失点击。
- 面板 TLS 每 30 秒刷新一次验证过的证书对，部分续期失败时只继续使用仍有效的旧材料；列表与回收共用运行中/已保存的面板证书引用。
- 每分钟调度只解码来源/资源/分发的截止时间和权益状态，不读取本地节点投影，也不构建运行缓存中的节点与正文对象。刷新/渲染路径仍使用完整状态。
- 升级结束由独立助手确认新面板健康与实际版本；任务跨重启保留等待阶段，成功或回滚结果原子提交。移除只供旧测试调用的订阅恢复编排，测试包装函数移到 `_test.go`。

同一 Windows amd64 / i5-9400F / Go 1.27.3 环境，用 `BenchmarkSubscriptionScheduleRead` 读取 4096 个来源缓存节点及 4096 个本地节点，`-benchtime=500ms -count=3 -benchmem`，下表为三次中位数。

| 路径         | 每次耗时 | 每次分配字节 |
| ------------ | -------- | ------------ |
| 完整投影读取 | 16.77 ms | 15,881,249 B |
| 调度数据读取 | 3.80 ms  | 1,128,294 B  |

这组读取耗时约降低 77%，分配字节约降低 93%。调度仍需扫描运行 JSON 文件，收益来自跳过本地节点文件及无关对象解码；不据此推导 VPS RSS、代理吞吐或长期满载表现。原始样本和验收范围见[本轮验证记录](validation/2026-11-19-consistency-optimization.json)。

### 权益与主机查询（schema 12）

保存候选配置时，一次 `systemctl show` 读取五项服务的加载、运行及启用状态，供应用和回滚使用。原来每个服务分别查询两次，共启动十个进程。运行概览复用同一个读取函数。必需单元缺失、服务正在切换或启用状态异常时，中止保存。未安装的可选 Argo 单元可正常跳过。

在 1,000 条凭据的相同 SQLite 数据上，运行 `go test ./internal/accounting -run '^$' -bench BenchmarkCredentialMembership -benchtime=300ms -count=3`。Windows amd64、i5-9400F 的三次样本中，旧路径读取并解码整个实例，耗时 11.5–25.4 ms，每次分配约 644 KB。按主键查询成员资格耗时 61–94 µs，每次分配约 1.2 KB。入站影响查询也只返回受影响的权益与授权 ID。这组数据衡量单次查询成本。

| 路径        | 实现与作用                                                                                                                   |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------- |
| SQLite 连接 | 每条物理连接重建后仍执行外键、WAL/FULL、busy timeout 与 trusted_schema 策略，避免超时后退化为立即锁失败或丢失外键检查        |
| 配置候选    | 网关与页面共享边界；订阅和网络使用完整草稿；接受的远端来源随任务保存，应用时复用并重新校验                                   |
| 页面加载    | 统一页面登记驱动原生 ES 模块；出站/维护/订阅按标签创建内容，页面内复用并合并并发读取，离页取消；权益页分组和导出能力按需读取 |
| 实时概览    | 共用 4 秒快照；内容不变只发送 22 字节 tick，权限每轮复核；权益页用量读取至少间隔 5 秒，同步事件不重复发起查询                |
| 表格        | 业务列提供纯标量索引；服务端分页；用量变化保留操作焦点，策略 revision 变化仍阻止过时操作                                     |
| 账户导出    | 客户端能力目录统一；二维码只生成所选节点，关闭或替换弹窗后不会追加迟到图片                                                   |
| 网络请求    | 页面读取可取消并限时；提交限时且不会自动重试，任务进度独立持久化                                                             |
| 订阅探测    | 64 节点、2 并发、每节点 12 秒，总预算 8 分 24 秒；取消时保存部分结果                                                         |
| 发布与清理  | 发布保留恢复日志；服务单元全量归属预检；安装失败与卸载只处理确认拥有的单元                                                   |
| 证书状态    | 单次读取当前 PEM 对并复用已解析叶证书；登记检查比较已验证材料，引用入口按路径建索引和稳定排序                                |

2026-11-18，本机实际面板 SSE 的首帧为 816 字节，相同状态下后续 tick 为 22 字节。该数字来自两条任务的独立开发目录，完整帧大小随任务与实例数量变化；不能推导整机 CPU/RSS 的固定下降比例。

## 保留的正确性边界

计量器保持每权益、每实例/账期池最多 64 KiB 的持久预留，提交完成后才交付转发；不降低 FULL 同步级别。并发预留仍使用最多 64 项的有界合批。授权缓存最长 250 ms，并受数据库、调度和在途 I/O 影响。连续崩溃的保守占用可以累积。

任务排队最多 32，单结果最多 256 KiB；历史默认 200 条/30 天/8 MiB 详情，可配置 20–2000 条、1–365 天、256 KiB–64 MiB。维护回收保留最终结果标记，SQLite 空间供后续写入复用。普通控制任务最长 5 分钟，探测使用独立后台通道和按容量计算的预算。候选来源缓存有单独的 8 MiB/4096 节点预算，并只随单个配置任务保存。

下载有效授权上限 10,000，失效历史最多 1,000 条/30 天。订阅单响应 8 MiB，JSON 投影 16 MiB；加密备份 96 MiB，数据库 80 MiB。备份/恢复互斥，恢复仍包含有界明文与密钥派生工作区，不能承诺固定 RSS。

该场景耗时约降低 48%，分配字节约降低 45%。没有增加跨请求证书缓存，当前文件变更仍会被下一次查询读取；证书匹配、域名和有效期检查保留。数据仅代表这组本地证书查询，不作为代理带宽、整机 RSS 或长期负载提升证明。原始样本与验证范围见 [版本入口及证书优化记录](validation/2026-11-18-version-and-certificates.json)。

复现：`go test ./internal/manage -run '^$' -bench '^BenchmarkCertificateStatus$' -benchmem -benchtime=1s -count=3`，需设置 `SING_BOX_BINARY`。
