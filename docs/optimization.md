# 性能、稳定性与资源边界

本文描述当前实现及可复测的优化，不以历史全量验收或磁盘清理量代替运行性能结论。当前修复与验证见 [实施报告](refactor-review.md)。

## 持久计量

转发前必须先取得已持久提交的额度。每个账户/账期池最多 64 KiB，SQLite 使用 WAL/FULL，授权缓存最多 250 ms；禁用、撤销、到期和账期边界仍按原规则生效。崩溃可能保守占用未使用预留，不能重复发放。

预留 writer 合并已经等待的请求，一批最多 64 个，不增加定时等待。批次在任何配额/租约读取和 SAVEPOINT 之前取得一次写锁，替代每行重复取得；单行失败回滚到自己的 SAVEPOINT，其他合法请求仍可提交。直到 FULL 提交成功才通知请求方。没有扩大预留额、降低持久性或缓存跨事务配额。

2026-11-27 本机 Windows / i5-9400F / GOMAXPROCS=4，基线 1bc4800 与修改版各测三轮、每轮 1 秒：

| 并发持久预留 | 基线 | 修改版 |
| --- | --- | --- |
| 分配次数 / op | 199 | 188–190 |
| 分配字节 / op | 8,116–8,123 | 7,741–7,796 |
| 微基准 MB/s | 149.23–162.33 | 137.08–176.56 |

带宽区间重叠且磁盘波动明显，不能给出稳定吞吐提升百分比。单池分配仍约 207–209 次，没有批量优化收益。两轮代码都保持相同持久规则；这些数字不是 VPN 端到端带宽或 Linux VPS 预测。

后续性能工作优先测量目标磁盘的提交 P95、混合读写等待、单/多账户吞吐，再决定查询、批量和预留策略。任何预留策略调整必须一起说明崩溃计费误差边界。

## 现有内存与查询控制

- 计量拓扑锁不执行 SQLite/socket I/O，每个额度池独立串行预留；Tick 批量查询活跃授权，复用有界临时容器，空闲释放峰值缓冲。
- 只为变化或关闭的池写检查点，批量事务保证重放/退款语义；无图表观看也持续计量。
- 额度请求复用对象和结果通道，归还前清除上下文和身份引用。
- 账户/授权列表服务端分页，候选集合使用独立轻量接口；绑定查询只读取所选关系，不解码所有凭据秘密。
- 导出和模板编译使用有界缓存及并发合并，每次请求仍实时检查确认版本、权益和授权；缓存不成为另一份权威状态。
- 证书状态复用同次 PEM 解析，远程来源、模板、输出和下载均有数量/正文/并发预算。

## 任务、清理和诊断

control/subscription/probe 各有独立 worker 和唤醒通道；总待处理 32，probe 最多 8，每秒跨进程轮询保留。空队列只读检查，避免空闲写锁。调度、凭据维护与历史清理不在领取每个控制任务之前串行执行。

任务来源独立于用户名。用户重试回执和入队同事务，避免响应丢失后的重复副作用。回执总量 10,000、至少 24 小时，终态历史清理不立即丢失重试屏障；回执本身只含摘要和编号。

权益、任务、证书历史分别限时 30 秒。失败先报告后台健康，再用独立两秒预算写审计；失败五分钟重试、恢复后每小时运行。故障分类有界且限频记录，不无限积累日志或原始错误。

## 前端流畅性

页面只读请求、窗口请求和登录会话写入分别管理。离页取消读取，旧页 render 失效；保存完成只能刷新仍属于本次提交的页面和编辑器，避免取消新的加载弹窗。

每个登录页面一条 SSE，隐藏断开，重连使用退避与随机抖动；状态观察器合并刷新并跳过隐藏标签。列表局部更新保留分页、过滤、排序和焦点，动态候选未变化时不重建。已有表单、选择和弹窗模块继续复用，没有新增生产框架。

任务请求只在需要幂等的三个写端点计算摘要，普通 GET 不增加异步准备步骤。浏览器回执最多 128 项，只存摘要/编号/时间，确认响应或退出后清除。

## 开发体积与运行资源分开衡量

源码工作区约数 MiB；主要开发占用来自 Go 工具链、模块/编译缓存、核心校验器、node_modules 和临时运行数据。按 [开发清理流程](development.md#清理与-main-交付) 删除可重建产物，保留源码回归、许可证和仍引用的文档图片。

清理释放的是磁盘空间，不等于 RSS 或运行 CPU 下降。没有目标服务器的 RSS、长时间负载或系统联动数据时，不作相应性能承诺。
