## 当前调度与交互边界（2026-11-26）

配置查询新增 `AppliedViewSince` 与共享只读解码缓存。网关控制路径、入站/出站/订阅操作选项、分享选项、隧道轮询和账户导出不再反复读取 desired+applied 全量正文；pending 标记仍与 applied 修订来自同一 SQL 快照。配置变化替换缓存，不修改旧读者持有的数据；隧道观察与账户授权继续实时读取。避免对缓存切片使用 append 拼接，防止并发读写底层数组。

连接上限分别限制客户端与转发流，UDP 关联由控制连接持有。日志和出站探测的只读弹窗接入 loadDialog，离页或弹窗被替换时取消读取，迟到响应无法覆盖新编辑器。此次只执行相关回归、类型与编译检查，不重新宣称全量验收或吞吐收益。

以下为此前的历史微基准，不能作为此次变更后的实测性能。

证书调度缓存已应用登记；未变化时 `AppliedStateSince` 不返回完整配置，扫描期限内不读取 PEM 和尝试记录。订阅调度规则已移到 `subscription.Schedule`，继续读取不含节点正文的轻量投影。表格保存渲染时的操作签名，修复原地修改与焦点刷新下的过期操作，避免重复序列化旧动作对象。

本机 Windows amd64 / i5-9400F / Go 1.27.3，三次 500 ms 微基准中位数：

| 场景 | 当前样本 | 说明 |
| --- | ---: | --- |
| 已预留额度的内存热路径 | 171.1 ns/op，0 分配 | 不含磁盘补充和 socket |
| 单路 64 KiB 持久预留 | 1.203 ms/op，54.46 MB/s | 保持 WAL/FULL 与预留后转发 |
| 并发持久预留 | 0.384 ms/op，170.62 MB/s | 三次吞吐为 186.11、29.44、170.62 MB/s，磁盘波动明显 |
| 128 出站配置视图 | 1.078 ms/op | 当前配置脱敏路径 |
| 4096 节点调度元数据 | 124.667 μs/op，约 3.7 KiB/op | 不解码节点缓存正文 |

这些是当前开销记录，不代表本轮百分比收益或实际 VPN 带宽。本轮未改动计费算法，历史样本不能与本次单独运行直接作速度结论。原始值、命令与平台限制见[验证记录](validation/2026-11-26-renewal-refactor.json)。

## 授权检查的内存复用

2026-11-21 在 Windows amd64、i5-9400F、Go 1.27.3 上，对同一现有基准各运行三次（1 秒/次），测试间没有并行浏览器或压力任务。

| BenchmarkActiveAuthorization100 | 修改前中位数 | 修改后中位数 |
| ------------------------------- | -----------: | -----------: |
| 每轮时间                        |   553,773 ns |   518,711 ns |
| 每轮分配                        |     87,002 B |     15,875 B |
| 每轮分配次数                    |          980 |          766 |

分配字节减少约 82%，分配次数减少约 22%。这只说明 100 个活动账户的授权检查路径；耗时受本机波动影响，不代表 VPN 吞吐、生产容量或常驻内存降低相同比例。

`Meter.maintenance` 串行拥有临时容器与 Usage 数组；每轮重新查询数据库、检查撤销和账期，完成后清空条目。授权对象持有值副本，空闲运行时释放快照容器，避免保留连接峰值的临时对象。没有增加跨轮授权结果缓存，没有延长撤销检查间隔。

复测：

```sh
go test ./internal/accounting -run '^$' -bench '^BenchmarkActiveAuthorization100$' -benchmem -benchtime=1s -count=3
```

## 订阅抓取与交互预算

订阅刷新与投递在 subscription 队列执行，连通性探测在 probe 队列执行；control 队列继续处理配置与账户变更。来源与模板/规则资源分别拥有 90 秒、45 秒抓取预算，每阶段最多 4 个请求并发，单请求仍为 20 秒。最久未检查的输入优先，已完成结果进入校验发布，未完成输入保持到期状态，下一轮自动调度继续。

任务总预算仍为 5 分钟，抓取不会占满整个预算。发布重新检查配置 revision、账户输入与核心身份。整体取消时，已完成来源抓取使用独立 5 秒预算保存；配置版本已变化则拒绝保存，未验证资源和产物不会被该步骤发布。通知共用最多 10 秒预算。

配置候选准备复用同一有界来源抓取器；它只读取发布状态，不持有刷新互斥锁等待网络。首次添加必需来源仍必须在请求预算内完成抓取和验证，否则候选不能应用。

## 保留的资源与正确性约束

- SQLite WAL/FULL、持久配额预留、撤销校验、账期边界保持不变。网络字节只能使用已提交的预留额度。
- 计量快速路径保持零分配；持久化路径仍由磁盘提交、SQL 和事务合并决定，不通过弱化持久性换取吞吐。
- 面板普通请求与 SSE 各有并发上限；昂贵操作、下载、缓存与正文大小均有单独边界。
- 账户导出缓存有容量和过期限制；权限、额度和引用版本仍实时核对。
- 页面只按需加载，切页取消读取；异步注册的任务回调通过当前页面动态分发，退出后不再请求旧列表。

完整样本及本次验证边界见[机器可读记录](validation/2026-11-21-refactor.json)。历史测量已移出当前文档，可从 Git 历史恢复。生产容量仍需在目标 Linux/VPS 上使用实际磁盘、连接数、TCP/UDP 负载和长时间运行测试确认。

取消后保存的来源进度携带 refresh_pending 标记；即使来源 Next 尚未到期，调度器也会安排继续发布，成功发布后清除标记。该标记属于派生运行状态，不修改期望配置。

## 运行状态投影与交互取消

新增 subscriptions/activity.json，由统一的运行状态发布入口和 runtime.json、schedule.json 一起提交。它只包含活动元信息，不包含来源节点、模板正文、投递地址或凭据；状态 API 无需读取完整配置和运行缓存。输出诊断仍从独立 output-status.json 读取。

投递后台任务仍有 5 分钟总预算、两个并发 worker，完成记录另有 5 秒提交预算，通知最多 10 秒。状态页按任务变化失效并合并刷新，隐藏页不发新请求；账户和分享列表的被替代查询会真正中止请求。新的派生文件增加少量发布写入，换取频繁状态读取的稳定成本。

新增 BenchmarkSubscriptionActivityRead 使用同一份 64 个来源、4096 个节点的合成缓存，对比旧式只解码元信息但仍扫描全部 JSON 与直接读取小活动投影。当前样本记录于验证 JSON；这些结果不表示网络吞吐、持久额度提交或整机内存占用同比提升。

2026-11-21 在本机独立运行 3 次、每次 1 秒：旧路径读取 1,164,956 字节，活动投影为 17,860 字节。每次操作耗时中位数从 3.150 ms 降至 0.168 ms，下降约 94.7%；分配字节中位数从 1,203,201 降至 42,169，下降约 96.5%。文件读取、扫描和解码均包含在基准内，HTTP、锁等待与磁盘冷缓存不在该比较范围内。

## 账户入站可用性缓存（2026-11-25）

`AppliedStateSince` 在一次数据库快照中读取已应用版本，仅版本变化时返回配置正文。每个平台服务缓存一份不可变入站可用集合；待应用配置不进入列表，账户绑定、到期、额度和撤销每次读取。DNS 资源编辑同时使用局部列表更新，减少整页重新构建。

`BenchmarkBindingAvailability` 在 Windows amd64 / i5-9400F / Go 1.27.3 上以 256 个入站、三轮各一秒测试。重复读取与解码的中位数为 617,325 ns、396,164 B、263 次分配；版本缓存为 23,730 ns、1,284 B、27 次分配。仅表示该配置读取路径的成本变化，不代表整个账户接口或 VPN 吞吐提升。[完整样本与边界](validation/2026-11-25-refactor.json)。

## 持久计量 SQL 与批次分配（2026-11-25）

预留事务使用带归属、运行实例、账期和关闭状态条件的 upsert。现在直接检查 RowsAffected 判断该操作是否被接受，移除紧随其后的租约 SELECT；批次结果数组由唯一写协程复用并清空。没有更改 64 KiB 预留窗口、保存点隔离、WAL/FULL 或提交完成前不得转发的约束。

同一工作区、Windows amd64 / i5-9400F / Go 1.27.3，将修改前后分别编译成测试程序，独立串行运行，各三次一秒；对比使用同一数据库 schema=17，旧实现通过 Go overlay 装载，不改写工作区。

| 基准 | 修改前中位数 | 修改后中位数 |
| --- | ---: | ---: |
| 单路持久计量耗时 | 1,161,257 ns | 1,153,417 ns |
| 单路分配字节 | 10,554 B | 9,255 B |
| 单路分配次数 | 249 | 210 |
| 并发预留耗时 | 335,298 ns | 313,562 ns |
| 并发分配字节 | 9,518 B | 8,188 B |
| 并发分配次数 | 238 | 199 |

分配次数分别减少约 15.7% 和 16.4%；并发耗时中位数降低约 6.5%，单路耗时基本持平。磁盘波动明显，早期与其他验证重叠的样本不用于速度结论。此处只衡量额度预留路径，不表示 VPN 吞吐或整机 RSS 同比变化。原始样本与边界见[验证记录](validation/2026-11-25-stability.json)。

## 多选与仓储生命周期收敛（2026-11-25）

本轮没有新增吞吐或 RSS 百分比指标，验证的是可明确观察的资源边界：

| 路径 | 本轮变化 | 验证方式 |
| --- | --- | --- |
| 多选候选 | 默认每页 40 个候选 checkbox；筛选与 selection 独立 | 1000 候选 DOM 回归 |
| 表单联动 | 候选内容未变时不替换选项；普通勾选原地更新 | 焦点、过滤、依赖重置回归 |
| 资源列表编辑 | 入站、出站和端点局部更新，并使相关页失效 | 既有列表状态回归与页面流程 |
| 订阅分发 | 一个任务为所有目的地共享一次打开的账户仓储，两个 worker 使用 | 取消、投递、授权与 race |
| 订阅来源捕获 | 已取得确认配置后只打开需要的账户仓储 | 发布一致性与生命周期回归 |
| 后台诊断 | 最多 16 类进程内摘要，持续重复错误的日志节流 | 容量、脱敏与恢复回归 |

共享连接不等于缓存授权：每个分发目的地发送前仍读取当前权益。数据库心跳、持久计量、撤销时效和 WAL/FULL 均未降低。后台摘要只补充可观测性，不增加持久账本或无界错误队列。完整命令和限制见[本轮验证记录](validation/2026-11-25-selection-refactor.json)。
