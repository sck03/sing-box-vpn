# 性能、稳定性与资源边界

[架构](architecture.md) · [开发与验证](development.md) · [验收记录](unified-management-status.md)

## 当前优化

| 路径 | 实现与收益边界 |
| --- | --- |
| 账户列表 | 复用一次查询快照，只为到期账期执行推进，避免逐账户重复读 |
| 账户导出 | 按账户/运行实例索引读取凭据；入口 ID 映射取代嵌套遍历，同次导出复用证书解析 |
| 用量结算 | 一轮变化池使用一个事务；计数快照采集后释放池锁再写 SQLite；累计检查点幂等 |
| 额度预留 | 保留 WAL/FULL 与先持久化后交付，64 KiB 预留上限不变；未以扩大误差换取吞吐 |
| 概览 | HTTP/SSE 共用短期缓存，systemctl 合并查询多个服务，任务完成使缓存失效 |
| 工作队列 | 一个控制通道与一个只读探测通道；自动任务去重；刷新和外部分发保持有序 |
| 前端 | 防重复提交；离页中止只读请求；临时断网保留草稿；静态 JS/CSS 条件缓存 |
| 备份恢复 | 二进制 multipart 移除 Base64 与 JSON 上传副本，同一面板进程限制一个重操作；解密仍有有界内存缓冲 |
| 订阅 | 共享能力筛选；未变化 sing-box 产物复用同核心校验；失败输出隔离，不拖垮启动恢复 |

以上是执行路径和调用次数的优化，不作为整机 CPU/RSS 或吞吐提升百分比。历史基准与长时间下载实验保存在[原优化日志](https://github.com/sck03/sing-box-vpn/blob/5975e773383b49dd6daca9f5406665eb47b06266/docs/optimization.md)，不能直接充当当前版本测量。

## 保留的边界

任务排队最多 32，结果最多 256 KiB；订阅单响应 8 MiB，生成 JSON 16 MiB；备份文件 96 MiB，数据库 48 MiB。来源和对象预算由相应模块常量维护。节点探测最多 64 个、并发核心 2 个，每节点 12 秒。后台没有按账户创建常驻进程。

预留落盘仍产生数据库同步；批量检查点只能减少周期结算事务，不能消除预留同步成本。连续崩溃的保守计费可以累积。配置刷新和网络分发仍可能占用控制通道，任务期限和取消仍受底层系统调用约束。

## 验证与清理

性能基准与竞态/构建分开运行；测试不能替代真实断电、满盘和长时负载实验。当前验证与未覆盖项见验收记录。

临时测试放 `.test/`、工具放 `.tools/`、当前发行包放 `.build/release/`。删除确认无用的旧材料；执行环境不能删除的材料统一移入仓库根目录 `待手动删除/`，该目录被 Git 忽略且不进入发行包。保留开发工具、必要缓存与虚拟机的基础磁盘依赖。旧设计文档仅在 Git 历史中保留，避免与现行部署说明混淆。
