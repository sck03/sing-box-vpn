**稳定性、独立导出与性能优化 · 2026-11-04**

本轮保持单个标准库 Go 二进制，没有降低连接上限、缩短空闲期限或引入定时重连。

- OpenVPN 配置改用行迭代与可复用字段切片，避免每个节点分配 4 KiB 扫描缓冲和逐行临时字符串。
  保存节点时复制短字段，避免它们连带保留包含大段 Base64 的整行 CSV。
- 相同配置和订阅不再写临时文件、fsync、替换；仍检查文件类型并收紧权限。
- 普通与 VPNGate 的节点、客户端、订阅和推送分开。VPNGate 只监听当前国家的五个入口，
  保存历史国家配置供切回恢复，去掉历史国家的无效监听和客户端选项。
- 共用工作进程内的 DNS 解析器，合并并发解析，并允许截断的 UDP DNS 答复回退到隧道内 TCP。
- UDP 控制连接关闭即取消拨号和会话；隧道进程退出即取消健康探测。
- 修复单向 UDP 活跃传输被 60 秒读超时误回收：收、发活动共同延长期限，空闲阈值保持不变。
  优化前的实测下载在约 62 秒中断，上传在 65 秒检查时发现会话重建；修改后的两项 65 秒测试通过。
- VPNGate 菜单新增独立入口设置。修改入口只重启对应 sing-box 服务，保持 OpenVPN 隧道；
  普通设置不再无条件重建防火墙，导出订阅不重启服务。
- 卸载先验证目录归属。整套卸载跳过即将删除的订阅重新生成，避免损坏的 sing-box 核心阻止卸载。

同机 Windows amd64、Intel i5-9400F、Go 1.27.3，三次基准取中位数：

| --- | ---: | ---: |
| 250 节点解析 | 1.010 ms/op | 0.565 ms/op |
| 解析分配内存 | 1,434,366 B/op | 237,889 B/op（减少约 83%） |
| 解析分配次数 | 7,076/op | 1,825/op |
| 重复提交 7 个未变文件 | 22.079 ms/op | 1.076 ms/op（减少约 95%） |

复现：`go test -p 1 -run '^$' -bench 'Benchmark(ParseNodes|UDPFrameRead|PublishUnchanged)$' -benchmem -count=3 ./...`。
UDP 帧读取仍为预热后 0 B/op、0 allocs/op。这些是局部基准，不等同于 VPS 总内存或完整 VPN 吞吐。
持续 UDP 验证使用 `RUN_UDP_IDLE_TESTS=1 go test -race -run '^TestUDPActiveOneWay$' ./addons/vpngate/gateway`。

仍需在实际 VPS 上采集 sing-box、OpenVPN 与网关的 CPU/RSS 和真实网络质量；多文件提交的
掉电恢复日志、上游验证服务的受控重试也仍有改进空间。不会通过放宽出口校验来掩盖失败。

**Go 迁移记录 · 2026-11-02（以下为当时的实现与测量）**

项目现在以一个静态 `yg-vpngate` 二进制提供管理和网关功能，Bash 负责安装、交互菜单和
systemd 服务配置。原 8 个 Python 运行模块、4 个 Python 验收程序和 Python 打包工具均已迁移。
Go 模块位于仓库根目录，只使用标准库，不需要 Python、pip 或第三方 Go 依赖。
可选 Certbot 的自身依赖仍由系统包管理器负责。

**已完成的资源优化**

- CSV 流式解析，不再复制整份响应再切分、拼接。列索引只计算一次，复用 CSV 记录，
  以 switch 代替每个 profile 重建白名单 map。
- UDP 帧缓冲随实际数据包增长并复用；常见小包约保留 2 KiB 接收缓冲，最大不超过协议限制。
  回复头只生成一次，地址使用 `netip.AddrPort`，避免每包构造地址字符串和回复切片。
- 宿主 HTTP 连接池复用；隧道探测连接只在当前隧道生命周期内复用，切换时关闭。
  每次探测仍验证实际出口及宿主出口，Geo 缓存按数据源/IP 区分且最多 128 项。
- 节点列表缓存一分钟，并发刷新合并；失败节点记录及时清理。健康状态仍更新内存时间，
  仅状态、出口或原因变化时持久化，避免默认每 10 秒进行一次相同状态的 fsync。
- 订阅最多 32 个连接，设置请求及空闲超时，流式发送文件，取消无上限 Python 请求线程。
- 证书读取及指纹计算使用 Go 原生加密库，每次导出按路径复用结果，取消重复 OpenSSL 子进程。
  下载与发行包散列均流式计算，不再为计算 SHA256 整体读入大文件。
- GitLab 三个订阅文件使用一次提交，避免分开写入造成内容版本不一致；安装服务只重启一次。

**稳定性修复**

- TCP 读取到 EOF 后转发半关闭，保留反向响应；连接出错或撤销仍关闭两端。
- 等待 worker 握手响应时可立即取消，并遵守调用方截止时间。
- 连接加入管理表时，在同一个锁内检查认证代次、国家、可用状态和容量；撤销立即释放容量。
- 管理循环能处理启动前已排队的操作，配置快照和子任务取消注册在同一临界区完成。
- 进程退出通知可被监控与清理同时观察；worker 退出也会阻断。监听器异常作为服务失败返回，
  允许 systemd 的 `Restart=on-failure` 生效。
- 守护进程使用 OS 文件锁，避免检查 PID 后删除锁文件的竞争；清理期间同样持锁。
- 配置和核心更新共用文件锁。先校验全部候选配置，再提交配置及导出，提交错误会恢复已写文件。
  核心先复制到私有暂存文件，再检查和激活，避免校验后原候选文件被修改。
- 按各协议的实际证书确定自签模式与指纹，修复单独更换证书对其他入口的影响。
