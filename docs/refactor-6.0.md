# 6.0 重构说明

当前修订为 v6.0.1：数据库 schema=16、平台 schema=6、订阅 schema=6、编译版本 5，受管运行时 1.14.4+sbvpn.6。首次安装使用空目录，不迁移旧数据、备份或接口。模板 version=1、节点文档 schema=4、备份容器 8 的结构未改变。

## 订阅与操作

输出身份同时包含客户端语法与用途；uri/base64 提供通用节点链接，mihomo-provider 等只输出节点集合，sing-box-nodes 提供 outbounds 片段，客户端名加 -config 表示完整配置。同一账户可以同时授权多个用途。仅节点保留连接必要参数，不包含策略组、DNS、监听和 TUN。节点片段需要客户端导入或配置引用，不承诺独立可运行。

账户默认及单独模板覆盖按 profile 选择；模板 client/mode 必须匹配，避免改变已授权地址的用途。可恢复内置默认。新安装不把全部内置账户模板复制进配置。普通分享优先显示节点，用户页将完整配置折叠，移动端减少重复空白；简单规则编辑独立于高级策略组能力。

## 正确性与生命周期

- 初次导出、账户编辑及批量绑定在查询前建立弹窗会话；切页、关闭和替换均取消读取，迟到响应不能覆盖新窗口。
- 保存后的绑定向导拥有独立会话，保存导致的页面刷新不打断后续操作。
- 卸载先恢复已保存的网络参数，确认成功后再清理程序和数据库；恢复记录或文件所有权异常时保留材料并报错。
- 成功升级只保留最近两份带所有权标记的备份；失败、中断和未标记目录保留诊断。清理失败不会把已成功启动的程序回滚。
- 服务端仅使用 sing-box 代理引擎。撤销 v6.0.0 增加的 Mihomo 安装任务和组件入口；Mihomo/OpenClash 导出通过内置节点解析器检查，真实客户端核心仅用于开发和 CI。检测统一使用 sing-box；不支持的传输标记为无法检测，不当作节点故障。

## 模块与资源

输出目录位于 internal/clientprofile，纯规划与模板约束位于 internal/subscription；管理层只编排权限、快照、缓存和校验。账户导出请求与凭据命令分离。状态和导出响应使用生成类型，结构化秘密递归脱敏且保留类型。

格式列表只做规划，不编译每个客户端；分享和下载只编译所选格式。未发布、修订不匹配或缓存损坏的远程模板只影响使用它的输出。保留有界缓存、凭据版本轮询、WAL/FULL、账本预留和发布回滚；重请求使用独立并发预算。测试专用网关监控包装器移入 _test.go。

## 参考与兼容性

继续使用单体 Go 与原生前端，不增加转换服务或第三方脚本运行时。借鉴 3x-ui/s-ui 的分享体验与 Sub-Store 的客户端独立输出器思路；MiniSubConvert 使用 Sub-Store 核心，不把二者当作独立兼容性认证。外部完整模板导入仍只接受可明确转换的子集，并显示限制；以目标客户端官方格式和实际检查为准。

v6.0.0 的历史验证见 [输出身份验收记录](validation/2026-11-20-output-profiles.json)，其 Mihomo 安装记录只描述当时的实现。v6.0.1 的验证与清理范围见 [单核心验收记录](validation/2026-11-20-single-core.json)。推送 main 与发布可安装的 GitHub Release 是独立动作。
