## 模块边界与性能

`domain.CredentialPublication` 拥有发布值对象；`application.ReconcileCredentials` 负责发布顺序、确认及重试策略；`manage` 只提供配置编译、原子文件发布和主机适配。仓储通过窄接口参与，accounting 不依赖 application。应用层测试覆盖发布失败不确认、部分确认后重试、只等待运行中的核心，以及已发布的停止实例不触发主机操作。

租约作用域仅在首次预留时创建，正常补充预留减少一条重复 SQL。每事务仍检查退休高水位与关闭状态，WAL/FULL、64 KiB 预留、跨进程 writer 和配额边界不变。空闲环境交替对照中，单池分配由 207 降到 195–196 次/op，并发由 189–190 降到 177–178 次/op；并发微基准有小幅改善，不承诺实际 VPN 带宽提升。完整方法和数值见[性能与资源](optimization.md)。

凭据更新仍重建受影响入站，因此该入站所有用户的现存连接需要重连。账户绑定、轮换、解除及 README 明确这一影响；其他入站继续运行。没有使用私有字段修改、unsafe 或跳过授权来实现所谓无缝更新。

## 验证与交付

本轮验证命令、通过/跳过范围与清理数字统一记录在[当前验证摘要](validation/current.json)。本地覆盖 19 组前端脚本、三套类型检查、生成契约、Go vet、发布标签下的 Go/race、真实 API 与 Chromium 桌面/窄屏验收。Windows 不能替代 Linux 的 systemd、namespace、防火墙、磁盘故障与安装回滚验收；这些由 main 提交对应的 GitHub Actions 完整工作流执行。

无长时间生产负载和目标 VPS RSS 数据，不据此声称没有 BUG 或生产容量已确定。历史验证 JSON 和重复实施记录从当前树删除，仍可在 Git 历史追溯；当前回归测试、许可证、文档示例图和固定依赖清单保留。

清理只覆盖工作区可重建产物：测试数据库、失败夹具、日志、截图、旧程序、编译/模块缓存、node_modules 和下载工具。按绝对路径、链接及进程检查后执行 `scripts/clean-dev.ps1`，不清理全局缓存或真实部署目录。历史报告曾列出的外部临时目录本轮复查均不存在，不计入释放量。

实际删除 `.test`、`.build`、`node_modules` 和 `.tools`，释放 3,236,760,643 字节（约 3.01 GiB）。包含 `.git` 的工作区文件总大小从 3,244,006,267 降到 7,245,624 字节（约 6.91 MiB），文件从 52,404 降到 821 个；这是清理后、最终提交前的快照，Git 提交会产生少量新对象。

本地和远端起始时均只有 main。交付使用普通提交和推送，保留提交历史与标签，不强制推送、不额外创建 Release。
