## 模块边界

- domain/serverconfig/subscription/accounting/controlstore/runtime 保留既有职责。此次没有引入额外进程或服务框架。
- 平台归一化和配置观察负责候选数据；编译器负责服务端和订阅产物；HTTP 负责传输与权限。
- form-dialog 负责字段生命周期，form-values 负责结构化值转换，ui 负责资源列表。DNS 编辑只更新当前列表，其他草稿保持有效。
- runtimeconfig 是支持的出站、端点和服务类型的共同目录；面板能力与后端检查读取同一来源。
- 缓存仅优化配置投影。账户状态、实际凭据、额度和到期每次读取；SQLite WAL/FULL、持久配额预留和撤销检查未弱化。

## 验证与清理

验证记录分别列出普通全量测试、真实核心、前端、API/浏览器、race、静态检查、Linux 交叉编译与本轮测试失败后的修正。整套真实核心 manage race 曾在 300 秒超时，栈位于 bcrypt；受影响真实流程和不依赖外部核心的单元路径分别完成 race 验证，不将超时记为通过。

删除的历史文件只测试已删除 CLI 和另写的模拟实现；证书校验、国家隔离、协议导出、路由、WebSocket、端口拒绝、订阅刷新、授权撤销与发布事务等有效覆盖转至当前模型或保留在现有测试中。工具链、许可证和可复用依赖/构建缓存保留。临时二进制、诊断日志、失败验收目录及多余截图在验收后清理，必要证据进入 docs/validation。

Linux systemd、namespace、防火墙、磁盘故障和长时间真实流量没有在 Windows 执行。交叉编译仅说明能构建；相应运行验收由现有 Linux CI/可丢弃 VPS 执行。本次只提交推送 main，不发布 Release 或部署实例。

清理结果：25 个临时条目、78 个文件、149,066,058 字节已集中移动到 Git 忽略的 `.cleanup-manual/`，可手动删除。自动审批检查拒绝了批量递归删除（`blocked by policy`），因此采用用户指定的可逆移动方案；.test 仅保留缓存和空临时目录。
