# 草稿、工作流与入站关联重构

更新：2026-11-27；基线 `dfd20cb`。本轮修复此前审查确认的问题，只执行受影响的检查，不新增旧版配置、数据库或接口兼容层。

## 已完成的修改

| 问题 | 实现 |
| --- | --- |
| 面板质量脚本打印成功后不退出 | 测试在 finally 中取消页面并关闭 DOM；通知改用 window 定时器，删除无效的 notice.timer 清理。运行器自动发现面板单元脚本，每组 60 秒超时判为失败，可指定文件做定向检查 |
| 新增入站迟到响应修改旧草稿 | formDialog 共用 dialogSession，候选请求绑定编辑器和页面；写回前核对草稿对象、内容和取消状态 |
| 新建权益/绑定结果覆盖新弹窗 | 账户编辑从列表模块拆出，写入采用会话生命周期，结果通过共享结果区保留；只有仍活动的编辑器可以替换弹窗和刷新页面 |
| 预设端口忽略未保存配置 | `/api/preset` 必须接收 `{id,protocol,config}`；与国家准备共用显式候选分配规则，包含入站、UDP 范围、VPNGate、订阅及面板端口 |
| 入站改名使已有凭据失联 | 已有入站 ID/协议不可直接编辑，复制可指定新 ID。后端在预览、提交及执行前验证普通入站绑定：删除/改名/换协议须先解除绑定，停用仍保留关联 |
| 状态观察器持有失效资源 | 取消或显式 dispose 释放定时器、事件和当前回调，重复销毁安全 |

`draft-controller.js` 独立负责加载合并、基线、代次、保存确认和结构化差异，不依赖 DOM 或网络。`prepareDraft` 统一候选提交规则。`account-editor.js` 负责账户编辑与绑定编排，列表只负责查询和展示。前端仍使用原生 ES modules、共享表单和现有窄屏样式，不增加生产依赖。

预设生成移除 PlatformService 上读取数据库的两个方法，改为显式输入的准备函数。入站关联规则位于 application，仓储只返回去重的 ID/协议，不解析凭据秘密。生成契约包含两个候选请求，草稿控制器纳入 strict 检查。

配置差异改为结构遍历，避免对每个父层重复序列化子树。本轮没有测量吞吐或 RSS，不宣称性能提升百分比。WAL/FULL、64 KiB 配额预留、授权窗口及 SSE 频率保持原有语义。

## 清理与交付

执行清理及 Git 对象压缩后，工作区从 **500,541,151 字节（477.35 MiB）** 降至 **7,056,583 字节（6.73 MiB）**，释放 **470.62 MiB，约 98.6%**。其中工具和依赖释放 462.13 MiB，余量来自 Git 对象压缩；测量包含 `.git`，最终文档及提交元数据会有少量增长。

删除失去私有镜像资产依赖的 `scripts/linux-vm.ps1`，修正文档中的旧 VM 路径和清理说明。`clean-dev.ps1 -Tools` 可以清除整个项目本地工具目录；`dev-env.ps1` 支持本地或系统 Go，并从版本清单核对工具版本。开发缓存统一放入可清理的 `.test`。

清理包括 node_modules、项目本地 Go、官方核心/Mihomo 校验器及其他验证工具副本。当前扫描未发现遗留数据库；本轮没有移除外部数据库或全局 Go/npm 缓存。保留必要回归、历史验证摘要、第三方许可证和文档仍引用的示例图。工具恢复方式见[开发与发布](development.md)。

本地和远端起始均只有 main，没有其他独有分支提交需要合并。正常提交并推送 main，不强制推送、不删除正式标签、不改写历史；交付后的分支和提交一致性在推送后核对。
