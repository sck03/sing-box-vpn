# 状态一致性、发布恢复与开发目录清理

更新：2026-11-26。基线为 `1851f7d`。面向首次部署，不增加旧配置、旧数据库或旧接口兼容层；数据库 schema 17、平台 schema 8、订阅 schema 6 和 CompilerVersion 8 保持不变。

## 修复与模块边界

| 问题 | 实现与边界 |
| --- | --- |
| 未应用修订暂停临时 Argo 域名同步 | 观察始终读取 applied 配置；与服务切换共用锁，更新失败恢复原观察值，不覆盖 desired 草稿；变化使概览失效 |
| 任务摘要之外的任务完成不刷新页面 | Overview 增加 resource_version；订阅、证书、网关和下载地址共用 status-observer.js，依据版本、配置修订和任务总数刷新 |
| 自然到期、外部进程修改没有任务事件 | 可见页面每 60 秒补充读取；隐藏页面和标签不发请求，离页移除定时器和监听器；并发通知合并为串行读取 |
| 草稿被显示为运行状态 | VPNGate 卡片读取 gateway 状态；独立下载监听读取 grant-options 的已应用设置和 public_url；分享创建共用 PublicURL，移除重复 origin 字段；草稿独立标注 |
| 订阅规则与基础设施混在管理器中 | subscription/policy.go 负责贡献来源和新鲜度；manage 只适配当前账户授权。下载、投递、状态使用同一策略 |
| 启动和 CLI 恢复重复维护 | 共用 recoverApplied，在发布锁内读取确认配置并重建产物。显式 CLI 恢复取得服务切换锁；启动不取得该锁，避免与等待健康检查的重启助手互相等待 |
| 协议测试手工快照缺少当前元数据 | 使用规范账户来源和生产恢复/编译流程，自动生成贡献记录与确认代次，发布失败直接报告诊断 |
| 授权测试未进入目标判断 | 修改测试配置后同步确认状态，继续验证未授权输出返回 404 |
| 半关闭测试资源回收与阶段超时不清楚 | 同步建立测试监听器、等待 worker/proxy 退出、自动关闭客户端；传输使用独立截止时间并报告服务端读写错误 |

前端保留原生 ES modules、共享表格/表单、按需标签加载和现有窄屏样式，不增加生产框架或运行依赖。状态观察器加入严格类型检查。订阅状态内容未变化时不重建 DOM，保留现有搜索和焦点。

本轮没有发现可直接删除的大量未调用业务代码；删除的是重复刷新、恢复和手工发布实现。现有零分配计量热路径、64 KiB 持久化预留、WAL/FULL、缓存预算和队列上限保持原有约束。

## 定向验证

- 管理层：Argo 与失败草稿、隐藏任务失效、授权、发布确认、来源新鲜度、启动与恢复边界；受影响场景执行 race。
- 网关：半关闭及取消连续 10 轮 race；账户隔离、凭据热更新、认证、TCP/UDP 和关闭流程定向 race。
- 真实协议：普通/VPNGate × VMess/Hysteria2 的 Provider 下载及 TCP/UDP，共 4 个场景、8 条连接路径。
- 前端：三组类型检查，状态同步、订阅生命周期、契约、弹窗生命周期和导航五组脚本；Go 生成契约检查。
- 静态与构建：受影响 Go 包 vet、格式与差异检查、Windows 管理器构建；真实面板 API 验证绑定、导出、分享限次、候选预览和持久化应用。

按任务要求没有运行完整 Go/前端套件，也没有执行 Linux systemd、iptables、真实浏览器或长期负载验收。半关闭测试的定向重复结果不代替全套压力条件下的稳定性结论。没有宣称 VPN 吞吐或 RSS 获得未经测量的提升。
