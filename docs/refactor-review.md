# 账户导出、任务边界与资源优化

更新：2026-11-26，基线 `c9fb63e`。本次执行此前审查中确认的问题，采用定向验证，没有执行完整测试套件。面向首次部署，不新增旧配置、数据库或接口迁移层。

## 修复与架构

| 问题 | 当前实现 |
| --- | --- |
| 64 字符入站 ID 保存成功但导出失败 | application.AccountNode 直接构造由实例和凭据确定的有界 ID，完成端点覆盖后统一校验；最大长度凭据 ID、中文名称和 Argo 派生节点均有回归 |
| 账户名称允许换行/NUL，导出才失败 | domain 统一 1–128 UTF-8 字节和禁止字符规则；能力接口发布同一约束，表单检查并定位名称字段；服务端返回 account.name |
| 分享页长期显示旧次数/状态 | 接入 status-observer 和 remoteTable.refresh；状态失效、重新可见及每 60 秒可见页兜底刷新，保留分页和搜索；离页清理，撤销局部更新 |
| 发布重试测试取不到执行输入 | Task 与 ClaimedTask 分离，worker 只接受已领取任务；测试检查领取输入、提交后的具体发布失败，以及两次恢复后不重复轮换 |
| 授权维护反复分配临时时间字段 | 查询缓冲复用可空字段；连接缓存仅持有值类型周期、截止时间和授权错误，不持有 Usage 或查询缓冲指针 |
| 重复保存组件版本 | 删除 App.Version，真实组件版本继续由程序状态返回；节点文档 schema=7，旧文档直接拒绝 |

账户节点转换的证书读取通过窄函数注入；应用层不依赖管理包、HTTP、SQLite 或文件读取。管理器保留已应用配置、账户授权、端点覆盖和发布职责。前端继续使用原生 ES modules、共享表单/表格、现有窄屏布局和可取消请求；分享查询/撤销加入生成契约及严格类型边界。

同入站凭据变更仍会重建监听并中断该入站连接。补充了同入站另一个账户的连接生命周期断言；其他入站继续运行。当前固定核心没有统一公开接口支持所有协议的无损用户更新，因此没有引入反射、私有字段修改或协议实现副本，也不宣称已实现无损热更新。
