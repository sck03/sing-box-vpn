# 审查问题修复与重构（2026-11-21）

本轮面向首次部署，直接维护当前数据和 API，没有引入旧数据迁移或旧接口兼容层。数据库和配置结构未变化，因此不为业务修复机械增加 schema；任务刷新结果增加 published、deferred、interrupted 字段，前后端与生成契约同步更新。

| 审查问题 | 当前实现 |
| --- | --- |
| 来源 URL 中的令牌进入只读状态接口 | 统一敏感字段策略覆盖 URL、密码、令牌及私钥字段族，管理员完整配置仍单独授权；viewer/operator HTTP 回归验证秘密不外泄 |
| 账户详情与列表状态不一致 | AccountUsage 与列表共用有效状态处理，统一订阅者停用和账期推进；普通查询不激活首次使用账户 |
| 延迟加载任务页丢失 SSE 回调 | 主页面动态分发给当前视图；独立回调槽避免继承递归，切页取消后停止更新 |
| 失败刷新丢失报告 | 手动、自动刷新复用执行和保存路径；即使执行错误，也保留有界结构化结果及发布状态 |
| 重复 ID 返回 500 | 仓库将主键/唯一约束转换为领域冲突；HTTP 返回 409 already_exists，并标记 id 字段；其他数据库故障仍保留存储错误语义 |
| 慢源拖延控制任务 | 刷新进入后台队列，分阶段限时、4 并发、按最久未检查优先；保留完成进度与取消语义 |
| 普通分享缺少链接级限制 | 高级选项可填写链接到期时间、最大下载次数；限制只能收窄权益，不能扩大权限或额度 |
| 授权检查重复分配 | 复用每轮容器与 Usage 存储，每轮仍重新校验；100 账户基准分配约降低 82% |

## 模块边界

账户查询与授权解释位于 accounting，身份冲突由 domain 表达，SQLite 编码翻译由 database 负责，HTTP 仅负责映射。subscriptions_fetch 负责有界抓取和公平调度，subscriptions_publication 负责验证和提交，subscriptions_checkpoint 只保存完成的来源进度，subscriptions_application 与任务执行器统一报告。分发快照捕获独立于网络发送，避免锁跨越远程请求。

前端保持原生 ES modules；不引入框架重写或无依据的缓存。共享类型契约覆盖账户、分享和刷新结果，生命周期回归直接加载真实页面模块并触发 SSE。

## 清理

Telegram/GitLab 回归已迁移到实际生产分发入口，删除两份重复旧 remote 实现；保留仍被有效回归引用的其他测试夹具，它们不进入生产二进制。过时的分阶段重构文档和历史验收 JSON 从当前目录移除，当前说明集中在架构、使用、开发和本轮报告中，旧内容仍可从 Git 历史恢复。工具链、许可证和有效测试保留。

本地临时数据库、日志、截图和旧构建产物共 136 个文件（220,584,540 字节），已集中移到 Git 忽略的 `.cleanup-manual/`，可整目录手动删除。批量删除被自动审批策略拦截，因此按用户指定的备用方案移动。Go 缓存与工具链仍保留用于后续开发。

## 验证

命令、结果、性能原始样本及环境边界统一记录在[本轮验证](validation/2026-11-21-refactor.json)。本地 Windows 测试不能代替 Linux systemd、namespace、防火墙和磁盘故障验收。推送 main 与发布安装归档是不同操作，本轮不创建新的 GitHub Release。

取消后保存的来源进度携带 refresh_pending 标记；即使来源 Next 尚未到期，调度器也会安排继续发布，成功发布后清除标记。该标记属于派生运行状态，不修改期望配置。
