# 运行状态、后台维护与恢复基线重构

更新：2026-11-27；审查及实施基线 `21c072c`。本轮修复此前审查确认的交互与状态问题，并处理后台无效工作、调度阻塞和服务快照时机。保留 Go 模块化单体、原生 ES 模块与独立受管核心，不增加生产依赖或旧版本兼容层。

## 已完成的修改

| 问题 | 实现 |
| --- | --- |
| 任务保留策略默认值无法通过原生数字校验，小数预算又被整数检查拒绝 | 复用 scale 字段，显示 MiB、提交整数 bytes；公共表单正确设置 step，页面取消关闭策略弹窗 |
| 快速订阅向导在命中缓存后，仍可能在离页或新编辑器上方打开 | 读取前取得 loadDialog 所有权；读取绑定取消信号，向导表单绑定页面；缓存命中也检查所有权 |
| 网关自主连接/验证变化需等到约一分钟后才反映 | 可见运行标签每 5 秒合并读取；隐藏/离页停止新请求，相同状态不重绘 |
| VPNGate 前端状态名称与后端不一致 | 后端 State 常量生成 GatewayState 联合类型，前端映射完整覆盖 fetching/connecting/verifying/waiting/ready/stopped/unavailable |
| 访问日志后切换到备份等标签，任务历史仍后台刷新 | 复用 observeStatus 的可见性、请求合并与释放机制；保留历史分页，首次读取失败提供可用重试入口 |
| 停止的核心已有发布版本，但 loaded 落后导致反复查询服务和失效概览 | 区分文件发布与核心确认；SQL EXISTS 检查无待发布工作时不取服务锁，不执行 systemctl，不推进 loaded |
| 定期维护先于每次控制任务领取，耗时检查拖慢交互命令 | 维护拥有单独的有界 worker 和到期计时器；控制 worker 专注领取/执行，共享取消与必要服务锁 |
| 排队期间外部服务状态可能变化，应用使用过时快照 | 在执行阶段、服务锁内保存 active/enabled 基线；持久检查点先于发布，重放和回滚复用同一基线 |
| 绑定流程对已筛选入口重复检查禁用与空集合 | 删除不可达重复分支，保留前置显式选择和仓储原子绑定约束 |

主机、持久化和 HTTP 仍为适配层；部署顺序继续由 application.ApplyDeployment 编排。状态观察器负责生命周期，页面负责业务展示。维护与控制任务并行不等于绕过锁：真实发布和主机变更仍串行，维护若正在执行必要的发布，相关控制动作仍可能等待服务锁。

已发布后的 loaded 差异由核心重载与服务恢复处理，管理器不重复发布相同凭据。实际发布仍等待活动核心确认，失败保留任务结果；停用的核心不被自动启动。WAL/FULL、64 KiB 配额预留、撤销规则与计量语义不变。

## 必要验证

- 三套前端类型检查及生成契约一致性检查通过；GatewayState 映射参加 checkJs。
- 执行 5 组相关前端脚本：状态同步、生命周期、订阅、接口契约、导航。新增预算回归使用 checkValidity/requestSubmit，不绕过浏览器约束；补充缓存弹窗竞争、网关自动状态转换、隐藏标签和首次读取失败重试。
- 定向 Go 回归覆盖任务恢复检查点、停用核心空操作、维护锁竞争、部署计划、凭据修订和网关状态显示。
- 使用现有官方校验器与受管核心，实际执行批量发布、批量绑定、隧道配置应用/下载一致性、候选来源复用、发布失败重试及订阅来源应用/刷新。没有把缺少环境变量导致的跳过计为通过。
- 对本轮修改的 manage/controlstore/accounting 路径执行带发布标签的定向 race；受影响 Go 包及契约生成器 vet 通过。Linux amd64 管理程序按四个发布标签编译通过。
- 没有运行完整 Go/前端套件、全项目 race、真实浏览器交互、Linux systemd/netns/防火墙执行、磁盘故障或长期负载测试。Linux 交叉编译仅证明编译成功。

本轮未运行吞吐或 RSS 基准，不宣称性能提升百分比。详细命令、限制与磁盘测量见[验证记录](validation/2026-11-27-runtime-maintenance-cleanup.json)。此前草稿与权益工作流的验证保留在[历史记录](validation/2026-11-27-draft-lifecycle-cleanup.json)，不作为本轮重新执行的证明。

## 清理与交付

验证结束后清理 `.test`、`node_modules` 和整个项目本地 `.tools`：包含测试缓存、临时运行目录、受管核心及官方校验器副本、交叉编译产物与本地 Go SDK。`.build` 和 `.cleanup-manual` 本来不存在。清理脚本先核对绝对路径、目录链接和运行进程，没有跳过的目录。

清理前 **2,941,786,616 字节（2,805.51 MiB）**，清理后 **7,120,027 字节（6.79 MiB）**，释放 **2,934,666,589 字节（约 2.73 GiB，99.76%）**。文件数从 54,811 降至 785；统计包含 `.git`，最后补充文档和提交元数据后体积会有少量增长。

工作区没有被 Git 跟踪的旧数据库或可执行文件；仍引用的示例图、必要回归、历史验证摘要及第三方许可证保留。此次清理限于项目工作区，不清除全局工具缓存或外部部署数据。恢复开发工具的方法见[开发与发布](development.md)。

开始及提交前本地和远端均仅有 main，没有额外分支的独有提交需要合并。变更正常提交并推送 main，保留正式标签和提交历史；推送后核对本地 HEAD 与远端 main。
