本轮修复了等价 UUID 绕过唯一性、预览与实际核心能力不一致、页面切换后延迟请求重开弹窗的问题。节点仅持有监听/传输/TLS 与 flow 策略；用户认证仅来自账户凭据库，未绑定的入站没有用户。

任务历史请求失败保留当前游标，并发翻页只接受一个请求。协议探测对启动阶段的 502/503/504 最多重试两次，仍受整体超时限制；其他 HTTP 失败直接返回。

凭据规范化位于 domain，绑定/轮换/解绑用例位于 application，核心能力描述位于 runtimeconfig。预览、保存及应用均经过实际受管二进制校验；发布构建包含 QUIC、uTLS、WireGuard、gVisor。后端错误使用结构化 API 信封，前端定位字段并保留冲突草稿，排队后提供任务详情入口。

概览只携带最多 12 个优先任务，失败/需要关注/运行中计数单独汇总；维护页按 ID 游标每页读取 50 条。静态资源按需压缩一次，压缩与原始表示使用不同 ETag。鉴权周期只读取必需字段，保持 WAL/FULL、预留额度和撤销语义。恢复流式暂存，认证完整密文后才允许检查或发布。

`npm run typecheck` 检查全部前端模块；Go 生成配置、账户、凭据、授权、任务及会话边界类型。动态 JSON 扩展仍保留明确边界，此项目尚未转换为全严格 TypeScript。

主要边界见[架构](architecture.md)，操作见[使用说明](usage.md)，命令见[开发](development.md)。本次结果见[完整实施验收记录](validation/2026-11-20-implementation.json)。更早的验证文件保留对应提交的历史证据。

凭据变更通过合并发布、按入站重载、持久重试和加载版本确认完成。五种协议均验证了新凭据连接、旧凭据拒绝、其他入站长连接保持和核心启动标识不变。受影响入站可能短暂中断，不承诺单用户无缝热更新。本地微基准不等于 VPS 代理吞吐；验证记录单独列明实际执行的系统检查和时间范围。
