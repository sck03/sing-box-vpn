## 模块边界

- cmd/sbvpn 仅装配管理命令和网关命令；发行文件名继续为 yg-vpngate。
- internal/vpngate 的生产代码不依赖 internal/manage，配置事务由入口注入。集成测试仍注入真实事务，验证共享锁与恢复行为。
- internal/clientprofile 维护客户端与输出能力；internal/subscription 负责解析、筛选、模板和产物语义校验；管理层负责权限、快照、缓存与外部核心检查。
- statefile 保留有界读取和持久原子写，filelock 统一操作系统锁，terminal/country 提供窄工具。保留管理层必要的私有包装，避免把底层细节散落到调用方。
- platform_service.go 负责资源装配与关闭；平台服务仍通过各职责文件编排业务。小时级历史/证书回收使用独立、有超时的 worker；配置变更与凭据发布继续串行，并等待所有 worker 退出。

## 用户操作

新建权益只需名称、额度和有效期，有可用节点时默认自动绑定。保存成功后即使刷新列表也不会取消后续向导；绑定失败保留已创建权益，重试只提交绑定。分享前重读账户详情及当前可下载范围，使用后端真实状态。

客户端选择可按 Windows、macOS、Linux、Android、iOS 或 OpenWrt 等目录平台筛选，通用 URI 保持可选。用户页默认突出节点订阅，完整配置折叠。Stash 完整配置提供官方导入 scheme，其他客户端不猜测 URL scheme。

## 订阅校验边界

Stash 不再复用 Mihomo 的完整配置。其 DNS 使用 follow-rule、代理域名引导解析和 Fake-IP 排除域名，不输出 Mihomo 的 respect-rules、enhanced-mode 或 TUN。策略组和通用规则构造仍复用。参考范围与官方文档见 [上游说明](upstream.md)。

编码前选中的节点生成连接摘要，编码后独立解析并比较数量和连接语义；摘要不出现在面板或日志中，错误不包含原始凭据。只规范化已确认等价的默认值与允许的表达方式。Egern 和仅规则输出仍保留编码级标记；节点语义通过不代表整个目标应用已验证。

真实 sing-box 1.14.4 与 Mihomo 1.19.33 共验证普通/VPNGate 两种入口、五种协议、四种输出路径中的 36 组连接，每组包含 TCP 和 UDP。4 组 VMess/TUIC 的自签名 TLS URI 导入受客户端能力限制跳过，相应原生订阅均通过。五种协议的账户隔离和凭据重载单独通过。

Stash、Surge、Surge Mac、Surfboard、Loon、Quantumult X、Shadowrocket、Egern 以及 OpenClash 路由器应用尚未完成目标设备实测，继续显示相应实验/待验收状态，不把解析器或核心测试冒充应用验收。

## 性能测量

Windows amd64、i5-9400F、Go 1.27.3，128 个出站的配置脱敏视图，1 秒 × 3；前后算法在同一基准中比较。最终测量时未并行运行浏览器或其他验收。

| 指标 | 原路径中位数 | 当前路径中位数 | 变化 |
| --- | ---: | ---: | ---: |
| 耗时 | 1.773 ms | 1.028 ms | 减少 42.0% |
| 分配字节 | 508,286 B | 315,160 B | 减少 38.0% |
| 分配次数 | 7,900 | 4,641 | 减少 41.3% |

这只说明配置脱敏路径减少重复 JSON 编解码的收益。未测量本轮 VPS 常驻内存、代理吞吐或长期生产负载，不能把这些比例外推到整个程序。单节点预设也只分配目标协议资源，避免生成不用的端口和密钥。SQLite WAL/FULL、持久额度预留、撤销和独立运行时的保证保持不变。

## 验收与维护

本地通过带受管核心的 go test ./...、go vet、类型与生成契约检查、十组前端回归、真实 API 和桌面/手机浏览器、实际客户端矩阵。原始命令、测量样本和限制见 [机器可读记录](validation/2026-11-20-five-batch.json)。

Linux race、namespace/OpenVPN、IPv4/IPv6 防火墙、磁盘故障、systemd 恢复、双架构构建及首次安装/回滚由同一源码提交的 CI 执行；应查看该提交的 GitHub Actions 结果。历史修订的绿色 CI 不作为当前代码的验收证据。本机当前未提供 QEMU 及镜像，未声称进行了本轮本地 Linux VM 验收。

首轮 CI #95 通过核心与系统测试后，在发行打包发现清单仍引用已删除的 addons 目录；已修正清单，并增加实际源码目录预检与回归，令路径失效在编译双架构前就报错。失败截图上传改为明确的浏览器目录，避免扫描 root 所有的安装测试材料而再次失败。最终验收以修复提交的 CI 为准。

旧源码入口已移除并修正构建、测试和文档路径。历史验收文件保留其原始路径与结果；工具链、许可证、测试夹具与有效开发缓存保留。临时失败环境和重复归档在测试完成后清理，无法删除的材料统一放入 .cleanup-manual。
