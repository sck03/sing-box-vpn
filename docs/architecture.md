**模块与维护约定**

项目使用一个仅依赖标准库的 Go 二进制 `yg-vpngate`。Bash 负责安装、菜单和 systemd 单元；
配置、导出、凭据、更新与网关运行逻辑由 Go 管理。使用说明见 [README](../README.md)，
测试与测量记录见 [optimization.md](optimization.md)。

`proxyAccess` 隔离 SOCKS/UDP 与认证、连接容量和隧道选择；`tunnel` 隔离管理循环与具体 Linux
实现。新增后端应实现启动、停止、worker socket 与退出通知，再通过既有出口验证流程启用转发。
转发层不能自行选择未经验证的出口。测试使用替代实现和本机回显服务，Linux 专项再验收实际隔离。

所有权记录复用管理层有界 JSON 读取，缺失表示没有待恢复资源；读取错误、非普通文件、
超限、归属错误、非规范私有 IPv4 /30 子网或缺少原转发状态均在资源操作前拒绝。
启动与显式清理沿用同一验证入口，失败保留记录；新记录写入前同样验证系统转发状态。
随后完整查询命名空间、JSON 网卡清单和 filter/nat 规则，全部成功且没有同名资源才登记新
所有权。权限、超时和输出超限均作为错误返回，不用失败的单资源查询推断资源不存在。
清理后复用同一清单确认资源已移除，查询失败保留记录；防火墙只匹配规则操作后的完整链名，
相似前缀或注释不阻塞清理。命名空间与规则文本逐行使用字节迭代，不复制全文或分配字段切片。

OpenVPN 标准输出与错误输出共用一个流式接收器，由 `os/exec` 串行调用并在进程等待中回收。
就绪标记只保留固定长度的跨分块尾部，不累计整行；超长行、日志达到 2 MiB 或磁盘写入失败
都继续消费输出并检测就绪，避免管道填满阻塞隧道。日志按读取块写入，保留原始换行和最后
未换行的内容；进程退出通知在输出消费完毕、日志文件关闭后发布。

SOCKS 与 worker 共用连接服务循环：先检查准入，再创建会话协程。描述符、内存或网络缓冲
暂时不足时保留已有会话，接入重试从 5 ms 倍增至最多 1 s，成功接入后重置；等待可被取消，
不增加后台重试协程。监听取消或永久错误会取消全部处理、关闭套接字并等待握手、拨号和
转发完成回收；守护进程等待监听循环退出后释放锁。TCP 中继直接接收会话 context，取消时
关闭双端并等待两个复制方向结束；客户端已经半关闭且远端不再发送数据时，也能完整回收。
正常 EOF 仍只关闭对端的写方向，允许响应继续返回。worker 不维护重复的连接表，认证代次
和容量仍由 `proxyAccess` 管理。

代理容量在拨号前预约：已接入套接字和未完成 worker 拨号共用 `max_connections` 上限，
满载直接拒绝，不再创建额外 IPC 连接。成功握手在同一锁内把预约转为连接，失败或取消释放预约。
撤销出口同时清空连接表和预约表，关闭连接并取消正在等待 worker 的请求；旧请求的完成或
清理不能占用或释放新代次的预约。网络拨号、连接关闭和取消均在管理器锁外执行。

后台节点刷新同样属于管理器生命周期：退出时禁止新刷新、取消当前任务并等待其结束，
然后关闭 HTTP 空闲连接，最后由守护进程释放锁。候选 profile 校验在管理器锁外进行，
只在锁内复制上次节点和失败冷却表，避免解析大配置阻塞连接准入和撤销。固定模式首次
选择找到一个有效候选即结束；重新连接仍优先原节点，不额外验证随后会丢弃的候选。

候选列表和上次验证节点的磁盘缓存均带有完整 `sources` 列表，仅在来源及顺序一致时加载。
变更来源清空内存候选、上次节点和失败冷却，并取消后台刷新；刷新还检查来源代次，防止
快速 A → B → A 切换期间的旧响应重新发布。新来源不可用时保持等待，不回用已移除来源。
旧开发版无来源缓存直接忽略，不做迁移；相同来源仍可用有效缓存快速启动并重新验证出口。
控制接口用专用结构输出六个候选摘要字段，省去逐节点 map、装箱和排序，空列表输出 `[]`。

出口比较基于解析并归一化的地址值，IPv4 映射地址与对应 IPv4 视为同一地址；Geo 查询、
缓存键及状态都使用标准 IPv4 文本。Geo 响应按专用结构读取已知字段，不为无关元数据
创建 map 和切片；国家、地址、hosting 和 ASN 类型错误会拒绝整份响应，不写入 Geo 缓存。
存在的 ASN 按原始 JSON 数字直接解析为 1–4294967295 的十进制整数，不接受字符串、
小数、指数形式或 null，避免浮点舍入后意外匹配允许列表。字段缺失仍表示信息未知，
是否准入由 `RequireISP`、`ExcludeHosting` 和 ASN 允许列表共同决定。

控制命令与出口探测共用有界 HTTP 响应读取，控制响应最多 1 MiB；读取超限或断流时
报错且不输出部分内容。控制连接不跟随重定向，仅将 2xx 视为成功；失败响应缺少
有效错误字段时保留 HTTP 状态码，避免返回空错误。节点源继续使用流式 CSV 读取。

节点源直接从 HTTP 响应流解析，最多读取 16 MiB、保存 1500 个候选，单份 OpenVPN 配置
最多 1 MiB。前导/表头物理行最多 4 KiB；CSV 逻辑记录最多 2 MiB（包含引号及换行）、64 列。
结构限制在标准库分配记录和字段切片前检查，避免大量空列把小响应放大成巨量临时内存。
引号状态跨读取分块保留，支持双引号转义、多行字段和前导空白；标准库负责完整语法校验。
达到候选上限后仍读取并验证后续 CSV 的结构和语法，但不再解码额外节点的 profile。
断流、超限或 CSV 引号结构损坏均拒绝整份新列表，保留已有有效缓存；完整响应可复用 HTTP
连接。合法 CSV 中无效的单个节点仍可跳过。Base64 解码缓冲只在一次解析中复用，各节点的
规范化 profile 独立持有字符串。磁盘缓存共用有界 JSON 读取，损坏或超限时从节点源重新获取。
OpenVPN 指令最多三个参数，校验使用固定四字段存储；发现多余字段立即拒绝，避免无效长行
扩容出远大于配置本身的临时切片。内联证书块继续按原内容保留。
这些限制只作用于候选列表和配置文件；实际 TCP/UDP 转发独立，不累计或限制用户流量。

`cmd/release/` 构建两种 Linux 架构并生成安装包和 SHA256；`cmd/ci-release/` 解析发布版本。
`lib/services.sh` 统一生成服务及恢复策略，`lib/ui.sh` 统一输入、取消与错误返回。

`internal/command/` 统一执行核心检查、服务重启、防火墙和网关的短期系统命令，与业务模块
独立。stdout/stderr 共用最多 1 MiB 的输出缓冲，达到上限后继续消费并返回明确错误，不能把
截断的路由、规则或版本信息当作成功结果。执行期限由调用方 context 决定；进程退出或取消
后，继承的输出管道最多再等待 1 秒。退出码、取消和超时错误可分别检查，防火墙不能把
超限伴随的退出码 1/2 当作规则不存在。该模块不管理后台进程树；OpenVPN 长期日志与 worker
生命周期仍由网关后端维护。标准输入只接受文件、有限内存 reader 或 nil，避免阻塞输入影响回收。

仅以 `app.json` 作为普通节点的管理状态，不从旧 `sb.json`、日志或 Python 状态推断配置。
缺少管理状态但已有服务端文件时拒绝初始化，保留原文件；当前配置重复初始化保留端口和凭据。
VMess 分享链接直接编码标准 UTF-8 JSON；链接与 Mihomo 导出共用 WebSocket Host 选择，
优先采用传输配置中的 Host，缺省才使用 Profile 的默认值，连接地址、TLS SNI 与 Host 独立。
路径校验同时用于菜单修改和订阅构造，阻止手改状态绕过检查。服务端按解码后的 URL.Path 匹配，
因此本地路径不接受查询、片段或百分号转义；普通/VPNGate 都保留合法原始 UTF-8 路径。
URI 查询参数直接写入 Builder，省去逐项拼接和临时切片；VMess 单独编码 JSON，不生成无用的
URI authority、转义名称或查询参数。新增格式应维护自身编码约束并接受真实核心验证。
Mihomo 完整配置 `clmi.yaml` 和 OpenClash provider `proxies.yaml` 复用同一节点集合，
provider 仅序列化 `proxies`，路由器策略由客户端负责。两个范围的 provider 均进入现有
发布事务与卸载清理列表；HTTP 订阅使用相同令牌，空文件或超过 16 MiB 返回 503。
客户端策略按普通/VPNGate 范围直接构造；VPNGate 不创建随后丢弃的中国规则集、Clash
直连模式规则与自动测速选择器。共享节点列表预留容量，避免构建期间重复扩容。
URI 的证书字段遵循目标导入格式：Hysteria2 只为自签证书固定叶证书指纹，CA 证书不固定；
VMess 自签 TLS 使用 `insecure=1`。客户端不支持的字段不能通过额外兼容分支保证生效，
原生订阅及真实核心导入测试是验收依据，已知格式限制须在使用文档中明确说明。

订阅流式读取最新文件，不发送基于秒精度修改时间的缓存验证标记，避免同秒变更误返回 304。
监听异常或取消时统一关闭服务器及现有连接；取消回调代替常驻等待协程。32 连接及读写超时仍有效。

主动推送先等待配置锁并恢复中断的发布，在同一锁内读取所选范围的订阅快照，每个文件最多
16 MiB；全部读取成功后释放锁，再进行远端请求。GitLab 的三个文件始终来自同一批本地配置，
网络等待不阻塞后续菜单修改。文件存在性用 HEAD 查询，只将 404 转为 create，其他错误终止提交。
不需要解析的成功响应流式消费，仍检查 4 MiB 上限和读取错误并关闭响应体，支持连接复用。
Telegram 先校验完整列表，忽略空行，按含换行分隔符的 3500 字节预算分段，不拆开单条链接；
空列表或任一超长链接均在发送前拒绝。多条消息遇到远端错误时停止，已发送消息不自动撤回。

配置写入与核心更新先获取 `.operation.lock`，文件校验/替换与恢复再获取 `.manage.lock`。
服务启动只等待配置锁，核心重启在释放配置锁后执行。控制动作同时使用管理层的
`ConfigTransaction`，按最新保存的设置合并；新增操作应沿用此提交路径及恢复记录。
控制动作共用一个串行槽位；客户端取消或守护进程停止会立即结束排队，不等待前一项磁盘
提交。取得槽位后再次检查取消，避免已取消请求与空闲槽位同时就绪时仍修改配置；已经开始
的原子提交仍完成其一致性流程。后台刷新在成功接受动作后属于管理器生命周期。

每次修改只暂存一份当前配置快照。`.pending-config.json` 记录本次文件列表和 SHA256，
旧内容存放在固定目录 `.commit-current/before/`，候选内容位于 `next/`。这是同一次修改前
各文件的状态，不保存多次历史版本。提交和恢复成功后清理记录与目录；恢复失败保留唯一快照。
暂存阶段中断、尚未写记录的草稿只在归属确认后替换，不累积目录。恢复开始前校验全部备份，
缺失或损坏时不先恢复其中一部分。当前恢复结构不含旧格式兼容分支。

现有文件比较、备份和恢复使用 32 KiB 可复用缓冲；复制时同时隐藏输入的 `WriteTo` 和输出的
`ReadFrom`，避免标准库绕过已借出的缓冲，再为文件写入分配一份。JSON 读取按实际文件大小
分配，同时保留 16 MiB 上限。JSON 与字节文件共用原子写入过程，资产下载在同一路径内校验后落盘。
管理状态文件不接受顶层 `null`：读取时立即报错且不清空目标，避免缺失状态被当作有效配置、
空凭据映射进入后续写入并导致 panic。文件缺失与内容无效仍分别处理。
核心配置校验直接将 JSON 编码到私有临时文件，不再额外生成完整输出字节副本；编码或核心
检查失败均清理临时文件。JSON 格式与正式发布共用同一个编码器配置。

核心更新在调用候选核心前记录普通/VPNGate 两套服务端与客户端的全部四个配置路径，
包含不存在的文件；完成兼容性检查后逐一核对，新增、删除或内容变化都终止激活。
摘要复用存储层的 32 KiB 流式缓冲，不持有完整配置副本，拒绝目录和符号链接。
服务状态查询共用有界命令执行，仅将无诊断输出的退出码 3/4 视为未运行/不存在；总线、
权限、异常退出码与输出超限均中止更新并保留服务名和诊断。取消/超时也不能视为未运行；替换核心前检查
取消状态，当前核心备份复制期间取消也不发布备份。已开始替换后的服务恢复沿用回滚流程。

核心压缩包与 cloudflared 共用 256 MiB 下载边界、SHA256 校验和 32 KiB 复制缓冲；已知长度
超限时不读取响应体。核心解压后的全部数据共用 512 MiB 预算，包含元数据、跳过的文件及
尾部 gzip 成员；单个核心最多 256 MiB，必须是唯一且非空的普通文件。找到核心后仍完整
检查后续 tar 条目与 gzip CRC/长度，全部成功后才执行版本检查。解压期间按块检查取消，
候选发布前再次检查；任何失败均保留已有候选并清理私有暂存目录，不提取其他归档路径。

UDP 关联的目标表和地址头缓存共用一把锁；网络拨号在锁外执行。每个关联最多 128 个目标、
256 个地址头缓存、8 个未完成拨号；每个目标最多排队 64 包。各目标使用独立发送协程与 FIFO，
避免一个目标的 DNS 或 IPC 写入阻塞影响其他端口。缓冲按 256 B 到 64 KiB 分档借用；容量计入
排队和正在写入的数据，关联最多 256 KiB，单目标最多 128 KiB。关闭关联取消拨号、关闭全部
连接并等待发送/接收协程退出，再归还缓冲。每个数据包沿用既有协程，不创建新协程。
worker IPC 按 IPv4 UDP 最大负载 65,507 字节校验帧；SOCKS 适配层完整读取后再检查封装大小。
回复加上 10 字节地址头超过 65,507 字节时，仅丢弃该包，保留目标连接、源端口和后续帧边界。
超过 IPC 协议上限或被截断的帧仍关闭目标连接；两层边界各由对应模块处理。

端口预留按实际节点类型确定，普通节点始终使用 normal 归属，VPNGate 使用国家归属。
冲突校验与端口赋值分开，两类入口共用赋值函数，避免用 Profile.Country 推断临时对象的身份。
自动分配在 20000–59999 中从随机位置环绕查找，每个候选最多检查一次，整段跳过预留范围；
只有实际系统绑定失败才消耗 200 次探测预算，预留端口不占预算。Linux 冲突检查只解析内核
清单的前四列，复用扫描缓冲，不为每条套接字分配字段切片；不完整记录、无效端口或状态、
读取错误均终止检查。TCP 仅统计监听套接字，UDP 同时统计已连接与未连接套接字。
一次规则生成只建立一份预留快照，各协议复用它校验范围。防火墙查询仅将退出码 1 视为规则
不存在；nf_tables 返回退出码 2 时，仅明确指出当前查询目标链不存在的错误也作不存在处理。
其余错误均保留，全部所需查询通过后再建立提交计划。表级 COMMIT 不保证多个地址族
跨表同时提交，执行失败须保留所有权以便重试。内核未提供 IPv6 时按 IPv4 处理。

接收缓冲由 `sync.Pool` 在结束的会话之间复用，GC 可以回收池中的缓存。连接、认证与队列
不放入池；借用的缓冲必须在所有读写结束后归还。活跃会话仍需要完整的 UDP 接收空间。
TCP 半关闭、UDP 双向续期、稳定源端口、认证代次和未经验证不转发是维护时必须保留的行为。
UDP 关联在开始等待时设置一次读取期限，之后只在合法来源/头部/目标端口/认证检查通过后
续期，回复方向独立续期。无效包与其他源端口不会占用认证锁或延长关联寿命；零目标端口
在分配队列和启动 worker 前拒绝。关联退出同时等待控制读取和所有目标协程完成。

新增协议须同时覆盖入口、凭据、端口、sing-box/Mihomo/URI 导出及真实 TCP/UDP 验收。
改动连接或并发逻辑时运行 `go test -race ./...`，改动 UDP 生命周期时启用
`RUN_UDP_IDLE_TESTS=1`；完整订阅协议测试同时设置 `SING_BOX_BINARY` 和 `MIHOMO_BINARY`。Linux netns、防火墙与
systemd 专项由 CI 执行。性能结论应提供同机基线、输入与 `-benchmem`，并区分局部分配和整机资源。
